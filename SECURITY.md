# Security Policy — Engine Alto

## Reporting Vulnerabilities

If you discover a security vulnerability, please report it responsibly:
- **Email:** security@enginealto.dev
- **Response timeline:** 48h acknowledgement, 7-day assessment, 30-day fix target
- **Do NOT** open a public issue for security vulnerabilities.
- **Bug bounty:** To be established post-v1.0 release.

---

## Security Model

### Runtime Isolation
- All user scripts run in sandboxed environments (WASM / capability-restricted runtimes)
- Community plugins undergo automated + manual review before publishing
- External PRs execute in isolated sandbox environments with no production access

### Autonomous Defense
- Ethical hacker agents (Security Dept) continuously probe for vulnerabilities
- Police-layer containment hooks isolate compromised modules within seconds
- Doctor-Healer network validates all automated fixes before deployment
- Canary deployments with auto-rollback protect production

### Audit & Transparency
- Immutable audit logs track every system decision (signed, timestamped)
- No agent can modify or delete audit records
- Full audit export available via master override

## Secrets Management

### Policy
- **NO secrets, API keys, tokens, or credentials may be committed to version control**
- All configuration uses `.example` placeholders only
- Secrets are generated by the system and stored in the internal secure vault

### Storage Options (Production)

#### Kubernetes Secrets
```yaml
# Create secrets via kubectl (NEVER commit the actual values)
kubectl create secret generic alto-secrets \
  --namespace engine-alto \
  --from-literal=database-url='postgresql://user:pass@host:5432/db' \
  --from-literal=redis-url='redis://host:6379' \
  --from-literal=openai-api-key='sk-...'
```

#### HashiCorp Vault (Recommended)
```bash
# Store secrets in Vault
vault kv put secret/engine-alto/database url="postgresql://..."
vault kv put secret/engine-alto/redis url="redis://..."
vault kv put secret/engine-alto/openai api_key="sk-..."

# Application reads via Vault Agent sidecar or CSI driver
```

#### AWS Secrets Manager
```bash
aws secretsmanager create-secret \
  --name engine-alto/prod \
  --secret-string '{"DATABASE_URL":"...", "REDIS_URL":"...", "OPENAI_API_KEY":"..."}'
```

### Rotation
- Database credentials: rotate every 90 days
- API keys: rotate every 30 days
- JWT secrets: rotate every 7 days
- All rotations are logged in the audit system

## Content Moderation

### AI-Generated Content
- Voice generation: **DISABLED** by default (`ENABLE_VOICE_GENERATION=false`)
- Image generation: **DISABLED** by default (`ENABLE_IMAGE_GENERATION=false`)
- These features require explicit opt-in and compliance review before enabling

### Moderation Flags (in `.env.prod.example`)
```
CONTENT_MODERATION_ENABLED=true
CONTENT_MODERATION_PROVIDER=internal
CONTENT_MODERATION_STRICTNESS=high
ENABLE_VOICE_GENERATION=false
ENABLE_IMAGE_GENERATION=false
```

## Dependency Audit Process

### Automated (CI)
- `npm audit --audit-level=high` runs on every PR
- `pip-audit` runs on Python dependencies
- Secret detection via `git-secrets` / grep patterns
- SAST scanning for common vulnerability patterns

### Manual (Pre-release)
- Review all HIGH/CRITICAL npm audit findings
- Check third-party license compatibility (Apache-2.0)
- Verify no vendored credentials or test secrets

## Known Security Considerations

1. **In-memory job queue** — Jobs are lost on restart. Use `JOB_QUEUE=redis` in production.
2. **Mock AI endpoints** — When `ENABLE_REAL_AI=false`, responses are simulated. Not suitable for user-facing production.
3. **CORS** — Currently allows `*` in development. Restrict to `FRONTEND_URL` in production.
4. **Rate limiting** — Not yet enforced on all endpoints. Apply via API gateway (nginx, Kong) in production.
